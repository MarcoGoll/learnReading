# Spec: MathTaskEngine (Epic37)

## Overview / Goal

The shared basis of all math levels: tasks are generated by the game, answered by the child (answer cards or number pad), and checked automatically. A round runner handles attempts, points, visual help, sounds, and the round summary for math levels 1-6. Level 7 variants reuse the generator and the number pad.

## Decisions

| Topic | Decision | Justification |
|-------|----------|---------------|
| Input | Level 1: 3-4 answer cards. Levels 2-6: large number pad (0-9, delete, OK) | Real calculating instead of guessing; level 1 children may not write digits yet |
| Checking | Automatic, no adult judge | Math answers are unambiguous |
| Wrong answer | Wrong sound, visual help is shown, second attempt for half points; after the second wrong attempt the solution is shown with the picture (0 points) | Same attempt pattern as reading level 4 (`pointsForAttempt`) |
| Time pressure | None | Learning before speed |
| Round length | 10 tasks | About 3-5 minutes; enough for stars and the care reward |
| Visual help | Levels 1-3 always shown; levels 4-6 via a help button and automatically after a wrong attempt | Leads from counting to mental arithmetic step by step |
| Task selection | Tasks not yet mastered and often wrong ones are preferred, mastered ones fill the rest | Leads to the level goal; same idea as `preferThenFill` |
| Points | Base points per math level: 1: 10, 2: 20, 3: 20, 4: 30, 5: 40, 6: 40, 7: 50; streak bonus x2 applies on first attempts | Math tasks are faster than reading; keeps the shop balanced |
| Stars | Existing `starsForRound`: "correct" = correct at the first attempt, task count 10, not-yet count 0 | Same rules as reading |
| History | Every task result is stored in `history` with the key prefix `math:` (e.g. `math:add:3+4`) | Needed for task selection; reading statistics and practice filter these keys out |

## Technical Details

### Task model (`js/logic/math/task.js`)

```js
{
  id: 'add:3+4',            // stable key: <operation>:<expression>
  operation: 'add',          // 'count' | 'pickQuantity' | 'add' | 'subtract' | 'multiply' | 'divide'
  operands: [3, 4],
  answer: 7,
  missingIndex: null,        // 0/1 for missing-number tasks (MissingNumberVariant), null otherwise
  text: '3 + 4 = ?',         // display text; operators: + - · :
  speech: '3 plus 4',        // for ReadTaskAloud ("minus", "mal", "geteilt durch")
  aid: 'insects'             // visual help type, see below
}
```

- `count`: a quantity picture is shown, the answer is the number (cards show numbers).
- `pickQuantity`: a number is shown, the cards show quantity pictures; the answer is the matching card.

### Generator (`js/logic/math/taskGenerator.js`)

- `allTasks(levelConfig)` returns every task of a level config (e.g. all 66 additions with sum <= 10). Pure function, unit tested.
- Level configs come from the math content profiles (MathJourneys, HarderMathContent), e.g.
  `{ kind: 'add', max: 10 }`, `{ kind: 'mixedAddSubtract', max: 20, crossingShare: 0.5 }`, `{ kind: 'multiply', tables: [1, 2, 5, 10] }`, `{ kind: 'divide', tables: [1, 2, 5, 10] }`.
- Division tasks are always the inverse of the configured tables, without remainder; divisor never 0.
- `randomFn` is injectable (as in `js/logic/random.js`) for deterministic tests.

### Selection (`js/logic/math/taskSelection.js`)

- `selectRoundTasks(tasks, masteredIds, history, count = 10, randomFn)`: first not-mastered tasks (often wrong ones first), then mastered tasks, no duplicates within a round. For `mixedAddSubtract` the crossing share is respected.

### Components

- `js/components/numberPad.js` (BEM block `number-pad`): digits 0-9, delete, OK; shows the typed number in `number-pad__display`; max. 3 digits; keyboard input (digits, Backspace, Enter) for laptops; buttons min. 64 px for tablets.
- `js/components/answerCards.js` (BEM block `answer-cards`): 3-4 cards with numbers or quantity pictures; distractors are close numbers (answer +-1, +-2).
- `js/components/mathAids.js` (BEM block `math-aid`): inline SVG pictures generated in JS:
  - `dots` - dice-like dot pattern up to 10 (ten frame layout above 5)
  - `insects` - two groups of insects (addition) or insects with some flying away (subtraction)
  - `tenFrame` - twenty frame with filled cells for levels up to 20
  - `tensAndUnits` - ten bars and unit cubes for numbers up to 100
  - `eggRows` - rows of eggs (multiplication)
  - `sharing` - food portions distributed among dinos (division)
- `js/game/mathRoundRunner.js`: runs a round of 10 tasks: render task, input, check, attempts, sound (`correct` / `wrong`), points, streak, history, then `finishRound` and the existing round summary (`showRoundSummary`), care reward (`careFlow`), and `continueAfterRound`.
- `js/screens/mathLevel.js`: route `/math/level/<n>` for levels 1-6; reads the level config of the active math journey and starts the runner. Header with goal banner (`goalBanner`) as in the reading levels.

### Flow of one task

1. Task text and (if applicable) visual help are shown; input is empty.
2. Child answers -> correct: `correct` sound, points (first attempt: base points with streak bonus; second: half), next task after a short animation.
3. Wrong at first attempt: `wrong` sound, input is cleared, visual help appears (levels 4-6), second attempt.
4. Wrong at second attempt: the solution is shown in the task text and in the picture for about 2 seconds, 0 points, streak reset, then next task.
5. After 10 tasks: round summary with points, stars, goal progress.

## Acceptance Criteria

- Level 1 tasks are answered with cards, levels 2-6 with the number pad; the pad also works with a hardware keyboard.
- Answers are checked automatically; no judge controls appear in math levels.
- A wrong first answer allows a second attempt for half points; after the second wrong answer the solution is shown and the round continues.
- Visual help is always visible in levels 1-3 and appears via button or after a mistake in levels 4-6.
- A round has 10 tasks without duplicates; not-yet-mastered and often wrong tasks come first.
- Points, streak bonus, stars, level records, care reward, and round summary work as in the reading levels.
- Math results are stored in `history` with the `math:` prefix and do not appear in reading statistics or the reading practice island.
- Unit tests cover the generator (counts and ranges per config, no remainder in division), the selection, and the scoring per attempt.

## Open Risks / Assumptions

- Generated SVG aids must stay readable on small tablets; at most 20 objects per picture (larger numbers use `tensAndUnits`).
- `practiceKeyFilter` and `statistics.js` must ignore `math:` keys; this is part of this epic.

## Implementation Notes

- A task solved at the second attempt is recorded as "wrong" in the history (with half points as consolation), so stars and the streak count first attempts only and the selection still prefers it.
- For `pickQuantity` tasks the picture area stays hidden (the cards are the pictures).
- The visual help of missing-number tasks shows only the known operand until the task is solved.
