# Spec-Driven Development Template (Claude Code)

Template for new projects that are to be developed with Claude Code following a fixed spec-driven-development workflow. Details on the workflow and conventions are in [`CLAUDE.md`](./CLAUDE.md).

## Workflow

1. **`/roadmap`** - Claude asks for a free-text description of the project and clarifies missing technical constraints (language, framework, database, platform). Result: `docs/roadmap.md`.
2. **`/brainstorming`** - Claude works out rough epics matching the roadmap, then actively asks about further features until nothing more is added. Result: `docs/epics.md`.
3. **`/spec <EpicName>`** - Claude clarifies the implementation of an epic via multiple-choice follow-up questions (recommended option always pre-selected, alternatives selectable, own description always possible). Result: `docs/specs/<EpicName>.md`.
4. **`/dev <EpicName>`** - Claude implements the epic based on its specification.

An epic goes through the stages `planned -> specified -> in progress -> done` (status is maintained in `docs/epics.md`).

## Starting a new project from this template

1. Copy the repo as a new project (e.g. `git clone <this-repo> my-project && cd my-project && rm -rf .git && git init`).

   Example:
   ```bash
   git clone https://github.com/MarcoGoll/claude_basics_specDrivenDevelopment.git /home/marco/DEV/ernaehrungsraum/financialOverview
   cd /home/marco/DEV/ernaehrungsraum/financialOverview
   rm -rf .git
   git init
   ```
2. Open in Claude Code and run `/roadmap`.
3. Then, in order, `/brainstorming`, then per epic `/spec <EpicName>` followed by `/dev <EpicName>`.

## Structure

```
.claude/commands/     Workflow commands (roadmap, brainstorming, spec, dev)
CLAUDE.md              Workflow, coding, and directory conventions for Claude Code
docs/change-log.md     Log of all code changes (CHG IDs), part of the template
docs/roadmap.md        Generated by /roadmap
docs/epics.md          Generated by /brainstorming
docs/specs/            Generated by /spec per epic
```

`docs/roadmap.md`, `docs/epics.md`, and `docs/specs/` are only created on the first run of the respective commands. `docs/change-log.md` is already part of the template, since every code change is logged - regardless of which workflow step is currently running.
